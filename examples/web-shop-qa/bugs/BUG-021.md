## What a user sees
A sign-up name or a checkout "Ship to" containing HTML tags is shown as formatted HTML (bold text, images) on the account page and the order page, instead of as plain text.

## Why it matters
Text a user typed can run as code in the page (stored cross-site scripting). Today it shows only on the user's own pages, so the risk is lower, but the same values will reach any future admin or staff view.

## Steps
1. Sign up with Name `<b>x</b><img src=x>` and open /account
2. Add Ceramic mug, check out with Ship to `<i>ship</i><img src=y>`, and open that order's page /orders/<id>

## Expected
All text shown literally, never rendered as HTML (source: SEC-003 heuristic; security: stored XSS)

## Actual
`<h1>Hi <b>x</b><img src=x></h1>` on /account, and "Ship to: <i>ship</i><img src=y>" unescaped on /orders/<id>. The saved Shipping address is escaped correctly.

## Evidence
evidence/001/v3-b2-* (see qa/runs/001/verifier-3.md, C22)

## Prompt for your coding agent
The user's name ("Hi <name>" on /account) and an order's shipTo (/orders/:id) are inserted into HTML without escaping. Use the existing esc() helper in server.js for both (and for any other user-supplied value rendered into HTML). Add a test.

## Fix notes
- Cause: the /account heading inserted `user.name` and /orders/:id inserted `order.shipTo` into HTML without escaping (server.js:258, server.js:202)
- Change: wrap both in the existing `esc()` helper. No other customer-facing page prints a user-supplied value unescaped (search `q`, login `next`, saved address and checkout prefill already use esc; product names and messages are fixed text; static/app.js has no innerHTML). /admin left unchanged (BUG-002 waiting on the owner's decision)
- Files: server.js
- Test: no suite; `node --check server.js static/app.js` passes. On a private copy (:4311), restarted fresh twice, the bug's steps showed `<h1>Hi &lt;b&gt;x&lt;/b&gt;&lt;img src=x&gt;</h1>` and `Ship to: &lt;i&gt;ship&lt;/i&gt;&lt;img src=y&gt;` both times (before the fix: raw tags)
- Halo: /account heading for a normal name and an empty name ("Hi there"), order page for seeded orders (commas and plain text unchanged), checkout and the saved address (already escaped, untouched), /admin still unescaped by design (BUG-002)
- Commit: 7b9f36a
