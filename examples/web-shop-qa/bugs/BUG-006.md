## What a user sees
Typing the wrong password for a real account shows "500 Internal Server Error" instead of "Incorrect email or password".

## Why it matters
Everyone who mistypes a password hits an error page; the shop looks broken in its most common flow.

## Steps
1. Open /login
2. Enter test user A's email and the password "wrong-password"
3. Click "Sign in"

## Expected
"Incorrect email or password", not signed in (source: AUTH-002)

## Actual
HTTP 500, "500 Internal Server Error". Server log: TypeError: user.compare is not a function. Same at 390×844 and for user B

## Evidence
evidence/001/auth-002-fail.png · evidence/001/auth-002-curl.txt

## Prompt for your coding agent
POST /login throws "TypeError: user.compare is not a function" when the email exists but the password is wrong, giving a 500. Show the same "Incorrect email or password" page used for unknown emails. Add a test.

## Fix notes
- Cause: the wrong-password branch of POST /login threw TypeError("user.compare is not a function") (server.js, POST /login)
- Change: treat a wrong password like an unknown email: same 200 "Incorrect email or password" page, no session
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (users A and B with a wrong password get the message and no sid; correct password still signs in; unknown email unchanged)
- Halo: AUTH-001, AUTH-002, AUTH-003, AUTH-004, SEC-008
- Commit: b962a9e
