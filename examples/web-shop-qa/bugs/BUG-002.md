## What a user sees
Any signed-in customer can open /admin and see a table of every account's ID, email and role.

## Why it matters
Exposes every customer's email to every other customer.

## Steps
1. Sign in as test user A (a customer)
2. Open /admin

## Expected
Access refused (403, 404 or redirect); no list of other users' emails (source: SEC-001)

## Actual
200 with an "Admin" table listing all users' IDs, emails and roles

## Evidence
evidence/001/v2-c14.html · evidence/001/sec-001.txt

## Prompt for your coding agent
/admin only checks that someone is signed in. Restrict it to users with role "admin" (return 404 or 403 to everyone else), or remove the page if it isn't needed. Note no seeded user has the admin role. Add a test that a customer can't open /admin.

## Fix notes
- Fixed by the user's own coding agent: /admin now returns 404 unless the signed-in user has the admin role (server.js).
