## What a user sees
Signing up with "not-an-email" creates an account.

## Why it matters
Accounts that can never receive a reset link.

## Steps
1. Open /signup
2. Email "not-an-email", valid name and password → "Create account"

## Expected
Refused (source: AUTH-008)

## Actual
302 to /account, "Hi Bad"

## Evidence
evidence/001/plans/auth-008.json · evidence/001/v1-curl-out.txt

## Prompt for your coding agent
The /signup email field has no type=email and the server doesn't validate it. Add type="email" and a basic server-side check (something@something.something); show an error otherwise. Add a test.

## Fix notes
- Cause: the signup email field had no type=email and POST /signup accepted any string (server.js, /signup routes)
- Change: type="email" on the signup field; server refuses anything not shaped like something@something.something (/^[^\s@]+@[^\s@]+\.[^\s@]+$/ on the normalised email) with "Enter a valid email address"
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times ("not-an-email", "a@b", "@example.test", "a b@example.test" refused with no session; a valid email still signs up; BUG-007 checks re-run and still pass)
- Halo: AUTH-005, AUTH-007, AUTH-008, AUTH-009, A11Y-001
- Commit: ee89737
