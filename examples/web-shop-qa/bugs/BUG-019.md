## What a user sees
The browser requires "Ship to", but the server accepts an order with it empty.

## Why it matters
Orders with nowhere to send them. Needs a tampered request or a browser that skips validation.

## Steps
1. Sign in, add Ceramic mug
2. POST /checkout with shipTo= (empty)

## Expected
No order placed without a Ship to (source: CHK-004)

## Actual
200 "Thank you!", order #103 created with an empty address

## Evidence
evidence/001/v2-c21.html

## Prompt for your coding agent
POST /checkout doesn't validate shipTo. Refuse a blank (whitespace-only) Ship to and show the checkout page again with a message. Add a test.

## Fix notes
- Cause: POST /checkout never validated shipTo (server.js, POST /checkout)
- Change: refuse a blank or whitespace-only Ship to: re-show the checkout page with "Please enter a Ship to address"; the GET and POST now share a small checkoutPage() helper so the form is identical
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (shipTo "" and "   ": checkout form with the message, no "Thank you", no order, cart kept; a real address still places the order)
- Halo: CHK-001, CHK-002, CHK-003, CHK-004, CHK-005 (prefill shared via checkoutPage), ORD-001
- Commit: c90c0e0
