## What a user sees
Signed in as one customer, opening /api/orders/102 shows another customer's order, including their name and shipping address.

## Why it matters
Customers' personal data and order history leak to any other customer. The README promises "You can only ever see your own orders".

## Steps
1. Sign in as test user A
2. Open /api/orders/102 (user B's order)

## Expected
404 (or 403) and none of user B's details (source: ORD-005; README Features)

## Actual
200 with JSON {"id":102,"userId":2,...,"shipTo":"Blair, 12 Oak Lane"}

## Evidence
evidence/001/v2-c13.html · evidence/001/ord-005.txt

## Prompt for your coding agent
GET /api/orders/:id returns any order to any signed-in user. Return 404 unless the order belongs to the signed-in user (the HTML /orders/:id page already does this). Add a test that user A gets 404 for user B's order.

## Fix notes
- Cause: GET /api/orders/:id only checked that the order exists, not that it belongs to the signed-in user (server.js, /api/orders/ route)
- Change: return 404 {"error":"Not found"} unless order.userId === user.id, matching the HTML /orders/:id page
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (user A: /api/orders/102 404 with no user B data; own /api/orders/101 200; unknown 404; guest 401)
- Halo: ORD-005, ORD-004, ORD-001 (orders pages), SEC-001
- Commit: 90caf61
