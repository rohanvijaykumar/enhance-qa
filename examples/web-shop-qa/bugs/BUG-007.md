## What a user sees
Signing up with an email that's already registered succeeds and signs you in as a new "Dup" user.

## Why it matters
Duplicate accounts under one email; the newcomer's password then crashes sign-in, and it's confusing for the real owner.

## Steps
1. Open /signup
2. Name "Dup", Email = test user A's email, Password "longenough1"
3. Click "Create account"

## Expected
Refused with a message that the email is already registered (source: AUTH-007)

## Actual
302 to /account, "Hi Dup", signed in. Afterwards, signing in with "longenough1" gives a 500

## Evidence
evidence/001/auth-007-curl.txt · evidence/001/auth-007-fail.png

## Prompt for your coding agent
POST /signup doesn't check for an existing account with the same (normalised) email. Refuse it with a clear message, e.g. "An account with this email already exists", and don't create the user. Add a test.

## Fix notes
- Cause: POST /signup never looked for an existing user with the same normalised (trimmed, lower-cased) email (server.js, POST /signup)
- Change: if the normalised email already exists, show "An account with this email already exists" with a Back link; no user or session created
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (A's email, also upper-cased with spaces, refused with the message and no sid; the would-be password does not sign in; user A still signs in; a new email still signs up)
- Halo: AUTH-005, AUTH-006, AUTH-007, AUTH-004, AUTH-001
- Commit: 7e646fa
