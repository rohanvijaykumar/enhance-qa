## What a user sees
After an add-to-cart request with a product ID that doesn't exist, the cart and checkout pages show "500 Internal Server Error" for that user, and the cart can't be fixed from the UI.

## Why it matters
The user's cart is stuck broken until the server restarts. Needs a tampered or stale request (e.g. a product later removed).

## Steps
1. Sign in
2. POST /cart/add productId=999
3. Open /cart and /checkout

## Expected
The bad ID is ignored or rejected; cart and checkout still load (source: CART-012 charter; base: robustness)

## Actual
/cart and /checkout return 500

## Evidence
evidence/001/v2-c12-cart.html · evidence/001/v2-c12-checkout.html · evidence/001/t2-charter3.txt

## Prompt for your coding agent
POST /cart/add accepts any productId, then /cart and /checkout crash looking up the missing product. Only add products that exist (same fix as the out-of-stock check). Add a test.

## Fix notes
- Cause: POST /cart/add stored any productId; GET /cart and /checkout then crashed reading .price of the missing product (server.js, POST /cart/add)
- Change: same check as BUG-012: an id that matches no product redirects to / without adding
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (productId 999, "abc" and blank redirect to / and are not added; /cart and /checkout return 200; a valid add afterwards works)
- Halo: CART-001, CART-012, CHK-001, CHK-007. Same commit as BUG-012
- Commit: 610288c (same commit as BUG-012)
