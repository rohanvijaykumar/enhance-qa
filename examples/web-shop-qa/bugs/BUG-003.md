## What a user sees
Searching for text containing HTML tags renders those tags on the results page (bold text, images) instead of showing the text.

## Why it matters
A crafted search link can run script in a shopper's browser (reflected cross-site scripting), e.g. to act as them.

## Steps
1. Open /?q=<b>bold</b><img src=x onerror=alert(1)> (URL-encoded)

## Expected
The query is shown literally; no HTML rendered, no script runs (source: SEC-003)

## Actual
"Results for <b>bold</b><img src=x onerror=alert(1)>" is in the HTML unescaped; Chrome builds the <b> and <img> elements and requests src=x

## Evidence
evidence/001/v2-c15.html · evidence/001/shop-011-odd.html

## Prompt for your coding agent
On the shop home page the search query is inserted into HTML without escaping ("Results for <b>${q}</b>"). HTML-escape it (& < > " '). Add a test that /?q=<script> comes back escaped.

## Fix notes
- Cause: the search query was interpolated raw into "Results for <b>${q}</b>" on / (server.js, GET / route)
- Change: added one small esc() helper (escapes & < > " ') next to money(); used it for the search heading only
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (the bug query and /?q=<script> come back as &lt;...&gt;; plain "mug" search still lists Ceramic mug)
