## What a user sees
Typing -2 in a cart quantity shows a negative price and total ($-24.00); a blank or "abc" quantity shows $NaN everywhere, including the header count.

## Why it matters
Totals on the money path become wrong or meaningless.

## Steps
1. Sign in, add Ceramic mug
2. Set its quantity to -2 → Update (also try empty and "abc" via POST /cart/update)

## Expected
No negative quantity or price; blank or non-numeric input leaves a valid quantity and total (source: CART-004, CART-005)

## Actual
-2: "Cart (-2)", "$-24.00", "Total: $-24.00". Empty/abc: "Cart (NaN)", "$NaN", "Total: $NaN"

## Evidence
evidence/001/cart-t2-curl.txt · evidence/001/v1-curl-out.txt

## Prompt for your coding agent
POST /cart/update sets qty = parseInt(body.qty) with no validation. Ignore non-numeric or negative values (keep the old quantity), and remove the line for 0. Add tests for -2, 0, empty and "abc".

## Fix notes
- Cause: POST /cart/update set qty = parseInt(body.qty) with no validation (server.js, POST /cart/update)
- Change: accept only a whole non-negative number (/^\d+$/ after trim); anything else keeps the old quantity; 0 removes the line
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (-2, blank, "abc", "1.5x" keep qty 1, $12.00, Cart (1), no NaN or negative; 3 gives $36.00; 0 removes the line, total $0.00)
- Halo: CART-003, CART-004, CART-005, CART-006, CHK-002, header cart count
- Commit: 3befb1a
