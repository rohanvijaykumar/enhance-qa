## What a user sees
At phone width (390 px) the cart page is wider than the screen and scrolls sideways.

## Why it matters
Shoppers on phones must scroll sideways to see prices and Remove buttons on the money path.

## Steps
1. At 390×844, sign in and add Ceramic mug
2. Open /cart

## Expected
No horizontal scrolling (source: A11Y-004)

## Actual
document scrollWidth 620 on a 390 px viewport; other pages fit

## Evidence
evidence/001/v2-c20-cart.png · evidence/001/a11y-004-a11y-004-cart.png

## Prompt for your coding agent
The /cart table is 620 px wide at a 390 px viewport. Make the cart fit narrow screens without changing the desktop look (e.g. let the table and its quantity inputs shrink). Check at 390×844.

## Fix notes
- Cause: .checkout-bar has a fixed width of 600px (620px with the main padding), and the cart table (458px, mostly the ~197px quantity input) is wider than a 350px content area
- Change: .checkout-bar gets max-width: 100%; under 480px only, table cells use 4px side padding and the cart quantity input is 4em wide. Desktop unchanged
- Files: static/style.css
- Test: no suite. node --check passes. The /cart page (mug + spoon) rendered in headless Chrome inside 390px and 1280px iframes, fresh server restarted between two runs: at 390 scrollWidth 390 = clientWidth (was 620), table 350, checkout bar 350; at 1280 checkout bar 600, table 570, input 197, the same as before
- Halo: A11Y-004, PAGE-004, CART-003 (quantity input narrower on phones), every table on phones (Admin, cart) via the td/th padding rule
- Commit: 037f1e8
