## What a user sees
A sign-in link with a crafted next= value injects script into the sign-in page, and signing in with next=https://example.com sends the user off the shop.

## Why it matters
Attackers can phish or run script via a genuine-looking Corner Shop sign-in link.

## Steps
1. Open /login?next="><script>alert(1)</script> and view the HTML
2. Separately: POST /login with test user A's credentials and next=https://example.com

## Expected
No script injected; after sign-in you stay on Corner Shop (source: SEC-004)

## Actual
(1) `<input type="hidden" name="next" value=""><script>alert(1)</script>">` in the page; (2) 302 Location: https://example.com (also //evil.test)

## Evidence
evidence/001/sec-004.html · evidence/001/auth-013-next.txt

## Prompt for your coding agent
The /login page writes the next query value into a hidden input without escaping, and POST /login redirects to body.next as given. Escape the value, and only redirect to same-site relative paths (starting with a single "/", not "//"); otherwise go to "/". Add tests for both.

## Fix notes
- Cause: GET /login wrote ?next= raw into the hidden input; POST /login redirected to body.next as given (server.js, /login routes)
- Change: escape next with esc(); after sign-in redirect only to a same-site path that starts with a single "/" (not "//" or "/\"), otherwise "/"
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (no <script> in the page, value escaped; next=https://example.com, //evil.test, /\evil.test, javascript:alert(1) all go to /; next=/orders still goes to /orders; no next goes to /)
- Halo: AUTH-001, AUTH-013, CART-010 and every "sign in to continue" redirect (login?next=/cart, /checkout, /orders, /account), SEC-004
- Commit: de26bcf
