# Trigger tests, 17 Nov 2026

16 prompts (`../prompts.csv`), Claude Code headless, model `sonnet`, 8 turns, read-only tools. Each prompt ran in a fresh copy of the bug zoo's clean control app with the skill as a project skill.

## Before the fix

The machine had many other plugins installed. The prompts ran in several batches, so these are the combined results:
- **Should start it:** 4 of 9. `/enhance-qa` also started it, but the first runner missed that.
- **Should stay quiet:** 7 of 7.

**What the misses did:** "is this ready to ship?", "check what I just changed", "do a bug bash" and "test this the way a real user would" all got Claude's own ad-hoc read-through instead.

**Without the user's plugins (`--clean`), on the five misses:**
- 4 of 5 started the skill, 3 of them as the first action;
- "test this the way a real user would" still didn't, because the description lacked that wording.

**Cause:** other skills compete for Claude Code's skill-listing budget, which drops the descriptions of rarely used skills first, and a new skill counts as rarely used.

## The fix

- **Description:** adds "test it like a real user" and "what's broken?".
- **Coding-agent note:** setup offers it for CLAUDE.md and AGENTS.md, and it now opens with a line that routes QA requests to enhance-qa.

## After the fix

| Setup | Should start it | Should stay quiet | Started it as the first action | Cost |
|---|---|---|---|---|
| User's machine, many plugins, no note | 6 of 9 | 7 of 7 | 5 | $2.31 |
| User's machine, many plugins, with the note (a project after setup) | **9 of 9** | 7 of 7 | 9 | $2.39 |
| Clean machine (`--clean`), no note | 8 of 9 | 7 of 7 | 8 | $1.47 |

**Still missed without the note:**
- **On the crowded machine:** "is this ready to ship?", "check what I just changed" and "do a bug bash".
- **On the clean machine:** "check what I just changed". It started the skill in an earlier clean run, so it's borderline. It likely competes with Claude Code's own `verify` habit.

**What this means:**
- In a project that went through setup with the note, triggering was perfect.
- Before setup, on a machine crowded with other skills, plain-English requests can miss. `/enhance-qa`, "QA my app" and "release go/no-go" are reliable.
- The skill never started where it shouldn't have.
