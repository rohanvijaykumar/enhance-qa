## What a user sees
"Save address" shows "Address saved", but the address box is empty after a reload and Checkout's "Ship to" is empty.

## Why it matters
A README feature ("Save a shipping address in your account; it's used at checkout") doesn't work, and the success message is false.

## Steps
1. Sign up a new user
2. Account → Shipping address "9 Pine Close" → "Save address"
3. Reload /account; then add Ceramic mug and open /checkout

## Expected
The address stays in the box after reload and prefills "Ship to" (source: ACCT-002, ACCT-004; README)

## Actual
"Address saved", then `<input name="address" value="">` after reload; Ship to `value=""`

## Evidence
evidence/001/acct-002-after.txt · evidence/001/acct-004-checkout.txt

## Prompt for your coding agent
POST /account/address reads the body but never stores the address on the user. Save body.address (trimmed) to the signed-in user, so /account and /checkout show it. Escape it when rendering. Add a test.

## Fix notes
- Cause: POST /account/address read the body but never stored it on the user (server.js, POST /account/address)
- Change: save String(body.address).trim() to the signed-in user; escape it with esc() in the /account address box and the /checkout Ship to box
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (" 9 Pine Close " saved trimmed, shown after reload and prefilled in Ship to; an address with "><script> is escaped on both pages; user A's address untouched)
- Halo: ACCT-002, ACCT-003, ACCT-004, CHK-005, CHK-001
- Commit: 3a8af6f
