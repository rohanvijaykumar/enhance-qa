## What a user sees
After "Sign out", the old session cookie still opens the account and orders pages.

## Why it matters
On a shared computer, or if a cookie leaks, signing out doesn't protect the account.

## Steps
1. Sign in with curl and keep the sid cookie
2. POST /logout with it
3. GET /orders with the old sid

## Expected
/orders redirects to /login (source: AUTH-010)

## Actual
200 "Your orders" (and /account 200) with the old sid

## Evidence
evidence/001/auth-010.txt · evidence/001/v1-curl-out.txt

## Prompt for your coding agent
POST /logout clears the browser cookie but leaves the session token valid on the server. Delete the session from the server's session store on logout. Add a test that the old token no longer works.

## Fix notes
- Cause: POST /logout only expired the cookie; the token stayed in the server session map (server.js, POST /logout)
- Change: factored the cookie lookup out of currentUser() into sessionToken(req) and delete that token from sessions on logout
- Files: server.js
- Test: no suite (no test framework in the project; none added). node --check server.js static/app.js passes. Bug steps run against a fresh `PORT=4311 node server.js`, restarted between two runs: expected result both times (old sid gets 302 to /login?next=/orders on /orders and 302 on /account; signing in again works; guest logout harmless)
- Halo: AUTH-010, AUTH-001, SEC-007, every signed-in page (currentUser now uses sessionToken)
- Commit: 94e3604
